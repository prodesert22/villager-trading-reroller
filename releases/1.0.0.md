# 1.0.0 — 2026-11-04

First stable release of **Villager Trading Reroller**: a companion mod (Fabric, client-side only) for *Villager Trading
Predictor* (VTP) that rerolls librarians in a closed loop, uses VTP's prediction to know how many rounds are left, and
consumes several rounds per cycle with a pool of villagers.

## Highlights

- Automatic reroller that **verifies the real offer** before deciding and stops only on a really observed hit.
- **Pool of burner villagers**: several rounds of the sequence per break/place cycle.
- **Prediction** (rounds, ETA, predicted item and enchantment) with **automatic calibration** on multiplayer.
- **Container mode**: the player stays still and the mod collects the lecterns from a chest/hopper.
- **Window, in-world highlights and an editable HUD** in VTP's visual style.

## Requirements and compatibility

| Item | Version |
| --- | --- |
| Minecraft | **26.3** |
| Java | 25 |
| Fabric Loader | ≥ 0.19.5 (tested with 0.20.1) |
| Fabric API | tested with 0.165.0+26.3 |
| Villager Trading Predictor | **1.3.x** (`~1.3`; the universal `VTP-2.0.0-mc26` jar works) |

Client-side **only**; nothing to install on the server. On a server the world seed is needed in VTP (`/vtp seed <seed>`)
for a prediction to exist; without it the reroller still works, verifying every open.
Do not run it together with other reroller mods (for example *Villager Trade Reroller*).

## How the mechanics work (facts verified in Minecraft 26.3)

- A villager's trades are generated **on demand** in `getOffers()` on the server, the first time someone asks for them:
  opening the trade screen (`mobInteract`) or the villager working at its workstation during the day (`WorkAtPoi`).
- The source of randomness is a **world sequence per trade set** (`TradeSet.randomSequence()`), derived from the seed.
  Every generation consumes **one round**; any villager takes the next unused round.
- Changing the profession clears the offers, which is why breaking and replacing the workstation rerolls.
- Consequence: prediction **cannot skip rounds** (each one costs a GUI open). The gain comes from event-driven waits and
  from burning N rounds per cycle with N villagers. The stop condition is always a **really observed** offer.

## Added

### Reroller and pool
- Closed-loop state machine: place → wait for the profession → open (one villager at a time) → compare with the VTP
  targets → break → wait for the villager to lose its job → recover the lecterns → repeat.
- Pool of cells (lecterns) registered per server/world/dimension; any level-1 librarian with no offers yet can be burned
  (villagers and workstations do not need to be paired).
- On a hit the villager is kept: nothing is broken, the trade screen stays open and a sound plays.
- Optional `maxCycles` and configurable time limits for every phase.

### Prediction and sync
- Rounds left (K), ETA from the measured rate, a progress bar, and the predicted item and enchantment of the hit round.
- Sync tracking: the position is trusted after 2 consecutive opens that advance exactly +1.
- **Automatic calibration** (multiplayer, night only): gathers the offers of consecutive opens and uses VTP's search;
  applies only when exactly one position matches. By day villagers generate offers on their own, so it is skipped.
- **No target in VTP's window** (`/vtp maxrerolls`): the mod keeps burning; the window slides forward with every open.

### Villager Job Fix (optional)
- Safe detection of the data pack (asks the server for the tab-completions of `/trigger vjf_`).
- Sends `/trigger vjf_single` or `vjf_multiple` right after placing the lecterns, capped per cycle.
- Off by default (`useVillagerJobFix`). Modes `AUTO`, `SINGLE`, `MULTIPLE`.

### Recovering the lecterns
- **Container mode**: register a chest (any kind, copper included), barrel, hopper, dropper, dispenser or shulker box; the
  mod opens it, takes the lecterns out (the first stack goes into an empty off hand) and closes it. The player never walks.
- **Floor pickup**: counts lecterns across the whole inventory, walks to the dropped items and back to the exact starting
  spot, braking early, sidestepping and hopping when caught on a block corner.
- **Sneak while placing** (`sneakWhenPlacing`), needed when the support is a hopper/chest/door.

### Tools and safety
- Picks the fastest suitable hotbar tool for every break and restores your slot when it stops or pauses.
- `start`/`resume` **refuse** when the block needs the right tool and it is not in the hotbar.
- Safety pauses: damage, another screen, ESC on the trade screen, spectator mode, out of reach, work hours
  (`dayGuard`: OFF/WARN/BLOCK), an entity occupying the cell (waits up to 10 s) and another block in the cell.
- **Translations** (English default, Portuguese, Spanish): the window, HUD, HUD editor, chat messages, in-world highlight
  reasons and VJF status. The language is **for the mod only**: `/vprng language [auto|en|pt|es]`, the *Mod language* dropdown in the *Settings* tab, or
  `language` in the config; `auto` follows the game's language (Portuguese/Spanish variants map to pt/es, anything else to
  English). Texts are in `assets/villager-trading-reroller/i18n/<code>.json`; tests ensure all languages have the same keys
  and placeholders. Key-binding names are translated by the game (`pt_br`, `es_es`, ... lang files).
- **Chat logs are optional**: progress and diagnostic messages (pauses, calibration, warnings, VJF notes) only go to chat
  when `chatLogs` is on (default **off**; `/vprng logs [on|off]` or the *Settings* tab). Direct answers to your commands and
  key presses and the FOUND notice are always shown; the same information is on the HUD and in the window.
- Placement failures report the reason (the game's result, the block in the cell, the support, sneaking, hand).
- "Keep running when the window loses focus": switches off "pause on lost focus" only while running and restores it.

### Interface
- **Window (K)**: *Control* (state, buttons, cards, the predicted round's offers), *Blocks* (list with icon, green/red
  status with reason, *View*, *Delete*, a per-block highlight switch, the container) and *Settings* (every switch, VJF,
  the HUD editor). Colours follow the accent chosen in VTP.
- **In-world highlights** through walls: green (ok), red (invalid, with the reason floating), cyan (container);
  *View* makes the block pulse with a beam and a label for 5 s.
- **HUD** with three panels (Pool, Prediction, Activity) draggable in **edit mode** (arrow keys move 1 px, Shift 8 px),
  resizable in width and height (drag the right/bottom edge or corner, or Ctrl + arrows), with a hide button per panel.
  The settings window is resizable the same way; its size is saved. Prices appear as a number plus an emerald icon.
- **Commands** `/vprng`: `status`, `start`, `stop`, `pause`, `resume`, `reload`, `gui`, `highlight [on|off]`,
  `hud <x> <y>`, `hud toggle`, `hud edit`, `logs [on|off]`, `language [auto|en|pt|es]`, `container [show|set|clear]`, `pool add|scan|list|clear`,
  `vjf [check|on|off|single|multiple]`.
- **Keys**: **G** starts/pauses/resumes/stops; **K** opens the window (both rebindable in Controls).

## Configuration

File `config/villager-trading-reroller.json` (reload with `/vprng reload`). Times are in ticks (20 = 1 s).

| Option | Default | What it does |
| --- | --- | --- |
| `lecternInOffhand` | true | Prefers the lecterns in the off hand. |
| `actionDelayTicks` | 1 | Minimum gap between world actions. |
| `aimFirst` | true | Aims one tick before acting. |
| `scanRadius` | 6.0 | Radius used to look for villagers. |
| `claimTimeoutTicks` / `claimGraceTicks` | 400 / 60 | Wait for a workstation to be claimed / grace for the others. |
| `offersTimeoutTicks` | 60 | Wait for the offers after opening a villager. |
| `placeConfirmTicks` / `placeBlockedTimeoutTicks` | 20 / 200 | Placement confirmation / wait for an entity in the cell. |
| `breakTimeoutTicks` / `resetTimeoutTicks` / `pickupTimeoutTicks` | 400 / 200 / 100 | Break, villager reset and pickup limits. |
| `autoCollect` / `collectRadius` / `walkTimeoutTicks` | true / 6.0 / 120 | Floor pickup by walking. |
| `containerRetryTicks` / `containerTimeoutTicks` | 20 / 400 | Container mode attempts and limit. |
| `sneakWhenPlacing` | true | Sneaks while placing. |
| `autoCalibrate` | true | Automatic calibration (multiplayer, at night). |
| `useVillagerJobFix` / `vjfMode` | false / AUTO | Data pack integration. |
| `vjfRetryTicks` / `vjfMaxTriggersPerCycle` | 20 / 5 | Trigger frequency and cap. |
| `maxCycles` | 0 | 0 = unlimited. |
| `stopOnDamage` | true | Pauses when taking damage. |
| `dayGuard` | WARN | Hours in which villagers generate trades on their own. |
| `foundSound` | true | Sound on a hit. |
| `chatLogs` | false | Progress/diagnostic messages in chat. |
| `language` | en | Mod language: `en`, `pt`, `es` or `auto` (follow the game). |
| `runWhenUnfocused` | true | Keeps running when the window loses focus. |
| `showHighlights` / `highlightOff` | true / [] | In-world outlines (global / per block). |
| `hudEnabled`, `hudX`, `hudY`, `hudPanels` | true, 6, 140, {} | HUD, panel positions and sizes. |
| `windowW`, `windowH` | 0, 0 | Settings window size (0 = default), set by dragging its edges. |

Data files: `villager-trading-reroller-pools.json` (cells) and `villager-trading-reroller-containers.json`.

## Upgrading

There is no earlier published version. The configuration is created with the defaults on first run; out-of-range values
are clamped when loaded.

## Known limitations

- **Minecraft 26.3** and VTP **1.3.x** only; VTP has no stable API, so the bridge (`VtpBridge`) only switches the
  prediction off if a call fails, and the reroller keeps verifying every open.
- Prediction covers **librarian** trades only (what VTP simulates); prices are the **base** ones, before discounts.
- Interaction reach limits the layout (lecterns about 1 block away for floor pickup; chest/hopper within 4.5 blocks in
  container mode).
- If a villager can walk into the space of a broken lectern, placement waits up to 10 s and then pauses; close the space
  behind the lectern.
- Lecterns moved into the inventory rows (not the hotbar or off hand) pause the loop.
- Villager Job Fix lists versions up to 1.20.1 only; detection confirms the trigger exists, not that it works on 26.3.
- Use it only where automation is allowed. The mod does not try to hide anything from a server.

## Verification

- `./gradlew build` compiles against 26.3 and runs **36 unit tests** (planner, sync, observation window, VJF detection, translations) —
  all passing.
- Real use in game (26.3 client with Fabric 0.20.1): the window, tabs, highlights, HUD, reroller, calibration and the
  container were exercised by the author on a multiplayer server during development; fixes followed from the logs.
- There are **no** automated in-game tests; rendering, character movement and server interaction depend on real use and
  may vary with the build and the server.
